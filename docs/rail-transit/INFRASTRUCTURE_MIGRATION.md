# 基础设施初始化与迁移

## 初始化与旧库

基础设施关系表由标准 `Database.initialize()` 初始化。可信旧库使用既有默认维护入口做幂等增量建表。生产安全启动沿用既有策略；尚未维护的库通过只读兼容投影展示正式旧站点和既有绑定。阶段一保留旧业务表、索引、采集文件、日志、报告和任务记录。

迁移不根据名称、IP 或 MAC 回填工程关联。正式车站可以按已有 `node_uid` 精确挂接新模型。legacy 派生数据仅作为兼容资料，不能填充未配置的正式关系。

## 查询与写入

`GET /api/rail-transit/base-data/infrastructure` 提供所选局点的只读组织投影，新旧事实带明确来源。现有基础资料接口、草稿、作用域权限、revision 及失败保留机制继续适用。车载 MR 资料页已关闭资产删除动作，通用资产删除继续由设备管理负责。

新增关系写入开放前须由 Application Service 校验局点、稳定 ID、scope 和预期 revision，在一个事务内校验唯一性及引用，再提交并返回 revision。解除关联结束关联有效期或删除关系行。MR 更换保留旧关联历史，资产和历史会话留存。删除节点先预检绑定、区间、项目及 AP 引用。AC 服务站点写入不刷新 FIT-AP Current。新关系维护入口在本阶段保持关闭。

## 开发数据库重建

只有确需重建时才在 `D:\NetConsoleData-dev` 进行。先停止相关进程，确认静止，登记数据库表、行数和关键记录，备份数据库及 WAL/SHM，使用正式初始化重建并执行完整性、初始化及业务回归。记录保留、迁移和清空项，保留可验证的回滚备份。当前阶段先在唯一 TEST 根验证空库、旧库升级以及重复初始化。
