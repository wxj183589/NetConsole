# Transaction observability

`GroundUnattendedRepository.set_transaction_observability(True)` enables bounded in-memory profiling. It is off by default. A SQLite trace callback classifies SELECT/INSERT/UPDATE/DELETE/UPSERT/COMMIT/ROLLBACK for write connections; UPSERT is also counted under INSERT. Repository transaction counters record BEGIN, successful COMMIT, actual ROLLBACK, failure, changed rows and duration samples (latest 5,000). `transaction_metrics_snapshot()` returns zero-valued counters for absent categories. No SQL text or raw Syslog payload is stored in these counters. There is no automatic Repository transaction retry; its retry counter is zero unless a later explicit policy is added.

The Raw Writer exposes registered/failed/pending metadata counts, bounded lock retries, total wait time and registration P95. The receiver health snapshot exposes projection started/completed/failed, checkpoint advanced/blocked, wait count, missing-file count, failure types, projection P95, queue accepted/max depth and queue wait P50/P95. Existing health counters continue to provide received, written, parsed and dropped counts. Failure types are exception class names, without message or raw payload labels. Samples are bounded at 5,000; no monitoring service or persistent per-statement log was added.

The five-repeat SQL comparison uses the existing full-connection trace with observability **off**, matching the historical audit method. A separate 400 MR run uses Repository observability **on** to measure transaction duration. Its SQL count covers Repository write connections, so it must not be compared numerically with the full-connection trace. `SYSLOG_BENCHMARK_COMPARISON.md` records both scopes.

Limit: queue wait is measured from UDP receive timestamp to Raw Writer dequeue; it includes in-memory queue and spool delay. It is not a network-delivery measurement. Current no-op count covers checkpoint parse-status UPDATE only; it does not claim all state writes are no-ops.
