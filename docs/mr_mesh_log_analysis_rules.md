# MR 原始 MESH 日志分析规则

本文档记录 MR 原始 MESH 日志分析模块需要长期遵守的 UI、导出和图表规则。

## NetConsole UI 非阻塞规范

- 任何状态都不能卡 UI，Qt 主线程只负责 UI 展示和用户交互。
- 超过 200ms 的任务必须后台执行。
- 超过 1s 的任务必须显示进度。
- 超过 5s 的任务必须支持取消，或至少不影响主窗口、其他 Tab 和图表弹窗操作。
- 大数据导入、解析、导出、报表生成、图表计算、压缩打包、批量网络采集必须异步。
- 禁止在主线程写 Excel。
- 禁止在主线程执行全量 SQL 查询。
- 禁止遍历 UI 表格导出数据。
- 禁止用 `QApplication.processEvents()` 作为卡顿修复方案。
- 后台线程不得直接操作 `QWidget`。
- 后台线程必须使用独立数据库连接。
- 禁止销毁仍在运行的 `QThread`。

## 表格列宽自适应规则

- 默认根据表头自动计算列宽，保证字段完整显示。
- 内容宽度大于表头宽度时，按内容扩展。
- 内容宽度小于表头宽度时，不收窄，保持字段完整。
- 必须允许用户手动拖动列宽。
- 必须保留横向滚动条。
- 禁止 `Stretch` 强行压缩列。
- 大数据表格禁止全量扫描计算列宽，只采样当前页或可见行。
- 用户手动调整后的列宽不应被普通刷新立即覆盖。

## MR / MESH 分析参数规则

- 主链路切换时间不得写死在代码里，默认全局值为 2500ms。
- 短时判定容差默认 500ms，短时阈值按 `主链路切换时间 - 短时判定容差` 计算。
- 乒乓判定容差默认 500ms；乒乓返回窗口默认自动计算，PIS 场景默认不低于 10000ms。
- 参数优先级为：本次报告/本次分析临时覆盖 > 导入时 source_file 参数快照 > 当前局点配置 > 全局默认值。
- 新建局点需要提供 `MR / MESH 分析参数` 页签，允许配置主链路切换时间、短时容差、同 AP 双射频合并、日志边界段、采样间隔、业务类型和 WiFi 类型。
- MR 原始 MESH 日志导入时必须把当前局点参数写入 `source_files.analysis_params_json` 快照，避免局点配置变更后历史分析结果漂移。
- MR 原始 MESH 日志分析页面的“分析参数”按钮允许本次临时覆盖；取消“仅本次分析使用”时才保存到当前局点。
- 短时建链判断禁止使用固定 5 秒。持续时间低于短时阈值才判为“短时建链”；处于容差范围内的 2s/2.5s 正常切换不直接判异常。
- 开启同 AP 双射频合并后，优先按 AP MAC、当前 PEER AP 名称、Peer Radio MAC 识别物理 AP；同一物理 AP 的 radio1/radio2 切换显示“同AP射频切换”，不能判为“短时建链”。
- 乒乓切换必须基于“主链路建链顺序”的 AP 级连续区段计算，不能按单条链路时长直接判定。
- AP 回切事件定义为物理 AP 序列出现 `AP_A -> AP_B -> AP_A`，且返回耗时在乒乓返回窗口内。
- AP 乒乓切换异常必须同时满足 `AP_A -> AP_B -> AP_A`、A/B 为不同物理 AP、`AP_B` 驻留时间明显小于配置主链路切换时间；默认 `2500ms - 500ms = 2000ms` 以下才计为异常。
- `AP_B` 驻留时间处于 `主链路切换时间 ± 乒乓判定容差` 时标记“临界回切”，超过上限时标记“普通回切事件”，二者不计入乒乓异常统计。
- 同一物理 AP 内 `radio1 -> radio2 -> radio1` 只能标记为“同AP射频往返”，不能计入 AP 乒乓异常。
- 主链路建链顺序 UI、导出链路明细 Excel 和分析报告必须使用同一套参数优先级。

## MR MESH 链路图表 Tooltip 规则

- ACTIVE 主链路图表和单 AP 动态图表都必须显示同采样点备份链路。
- 主线可以只绘制 ACTIVE 或当前 PeerMac，但 tooltip 数据必须包含同 `source_file_id`、同 MR、同采样时间的 ACTIVE/STANDBY 上下文。
- `source_file_id` 必须参与匹配，禁止跨日志文件串数据。
- `anchor_link_id` 不是全局唯一，不能跨 detail DB 单独使用。
- hover 时禁止查数据库，必须使用预加载 payload。
