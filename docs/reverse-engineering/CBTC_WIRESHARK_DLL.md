截至 2026-07-23，对当前工作树、全部可见 Git 历史和仓库文件名进行检索，未发现旧 CBTC Wireshark DLL、dissector 源码、协议样本、测试包或以下分析产物：

因此，本仓库目前没有足够证据确认旧 DLL 的字段语义、时延算法、异常/超时判断或新旧实现差异。附件中提到的时间平移、延迟压缩、丢包、插入间隔和拉伸样本也不在当前仓库内。上述项目统一标记为 `UNVERIFIED`，不得在产品文档、代码注释或测试中写成已证实规则。

## 证据等级

| 标记 | 含义 | 最低证据 |
| --- | --- | --- |
| `CONFIRMED` | 已确认事实 | DLL/反汇编位置、样本、脚本与可重复测试结果一致 |
| `SUPPORTED` | 多组样本支持 | 至少两类独立变体复现，未发现反例 |
| `INFERRED` | 从有限样本推断 | 明确记录假设、替代解释和适用样本 |
| `UNVERIFIED` | 尚未验证 | 缺样本、缺工具、缺复现或只有口头描述 |
| `REJECTED` | 已被证据否定 | 保存反例、失败探针和否定理由 |

当前仓库级状态：旧 DLL 行为、协议字段表、时延计算、状态判断和与新实现的差异均为 `UNVERIFIED`。

## 后续纳入要求

新证据进入仓库前必须脱敏并记录来源、SHA-256、采集条件、时钟基准和许可边界。每项结论至少记录：状态标记、对应样本、脚本入口、执行命令、输出文件、预期结果、实际结果、反例和最后复核提交。

CSV 只保存结构化观察，不替代原始样本；日志和测试包用于复现；探针脚本必须能从原始输入重新生成派生 CSV。真实现场地址、账号、Token、设备凭据和未授权二进制不得提交。历史研究数据不得因结论变化而删除，应通过新版本或 `REJECTED` 记录保留推理链。

在样本进入仓库后，建议按“字段位置与类型 → 时间基准 → 单变量扰动 → 状态边界 → 组合扰动 → 新旧实现对照”的顺序验证。没有对应证据前，不为异常、超时、延迟或状态算法生成虚构样例，也不把文件名中的版本号解释为结论成熟度。
