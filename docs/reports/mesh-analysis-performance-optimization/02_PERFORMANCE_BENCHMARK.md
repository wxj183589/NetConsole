# Mesh 四档性能基准

日期：2026-11-08；基线 `37b0df95a3208d0d03380e76ccfe5419af1422f1`；分支 `codex-A/mesh-analysis-performance-optimization`。

## 环境与口径

Windows 11 build 26200，AMD Ryzen 9 9955HX3D（16核32线程），物理内存 42,066,440,192 bytes，Python 3.13.9 AMD64。全部合成数据；每帧10条链路、1 ACTIVE/9 STANDBY、256 Peer/128物理AP、20秒驻留。5万条只遍历到125个物理AP，其他档128个；无单链路风险，不能代表最坏区段/身份/浮点分布的内存。

每阶段/variant各自独立子进程单轮实测，顺序 before→after；未做重复统计或冷缓存控制，存在抖动，不能把单轮差值当成稳定SLA。计时为 perf_counter；峰值为 Windows PeakWorkingSetSize，含进程导入、输入和摘要验证所需内存，非增量分配。导出峰值在ZIP XML行数验证前记录。

Parser原实现未修改，前后是同一解析器重复执行同一raw，不能宣称解析性能优化。quality before通过 git show 加载基线模块，after当前模块；query在同一查询Service分别用旧full策略/新自动策略。导出before基线完整诊断列，after当前默认业务列且额外完整业务统计；差异同时来自字段减少和新增统计，不是相同列Writer微基准。

raw Parser与parsed SQLite由等规模独立fixture生成；以下不是一次raw导入到GUI保存的全产品端到端计时。保留原ProcessPoolExecutor，不调整worker数量。
