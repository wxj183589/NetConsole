# 开发历史

本文按当前 changelog、近期 git log 和仓库结构整理项目演进，用于理解上下文，不作为逐条 release note。

## 阶段 1：基础桌面工具

早期版本建立了 PySide6 桌面主线和本地 SQLite 数据模型，形成设备管理、AC 管理、FIT-AP 光衰、LLDP 邻居解析和轨旁 AP 业务基础能力。

关键方向：

- 本地 Windows 桌面应用。
- 设备管理和连接测试。
- AC / FIT-AP 资源采集。
- 轨旁 AP 业务初版。

## 阶段 2：配置采集和文件管理

随后新增配置采集中心和类似 WinSCP 的文件管理能力。

关键方向：

- 运行配置、已保存配置、保存配置、快照归档。
- 配置清洗后差异对比。
- 诊断文件下载。
- 双栏文件管理、设备文件下载和 MESH 日志快速选择。

## 阶段 3：网络工具和无线扫描

网络工具开始覆盖本地现场诊断。

关键方向：

- iPerf 带宽测试。
- fping 工具集成。
- 无线扫描，合并 Windows WLAN API 和 netsh 结果。
- 轨旁 AP BSSID 反查。
- 本地网卡和路由管理。

## 阶段 4：AC / FIT-AP 和轨旁 AP 深化

AC 管理和轨旁 AP 业务围绕 FIT-AP 资源、AP 扩展信息、光衰和上线概览持续增强。

关键方向：

- FIT-AP 资源、地址、射频和光衰采集。
- AP 扩展信息资料库和设计/布点表导入。
- 轨旁 AP 定向更新、接口历史、AP 详情。
- 轨旁 AP 导出多 sheet，包括上线概览、光衰处理记录和当前异常光衰。
- 光衰状态来源和颜色统一。

## 阶段 5：轨道交通 MR 与车内通信

轨道交通模块扩展为完整业务域。

关键方向：

- 列车在线情况。
- 车内通信检测系统。
- MR 原始 MESH 日志分析。
- 车载 MR 实时收集。
- 车载 MR 收集分析。
- 跨 TC ping、单端 MR 在线判断、固定拓扑、自然列车排序。

## 阶段 6：性能、懒加载和主题

近期重点是降低卡顿、提高稳定性。

关键方向：

- AC / Rail 模块懒加载。
- 重型子页按需初始化。
- 大图表抽样和交互优化。
- 主题切换全局适配，避免递归 `setStyleSheet`。
- 子页状态保留，后台任务不因切换模块停止。

## 阶段 7：打包、功能门控和客户版

发布体系从单一构建演进为 PyInstaller / Nuitka、内部版 / 客户版和功能 profile。

关键方向：

- 发布包白名单。
- 禁止 docs/tests/project 进入用户包。
- 内置工具打包和 smoke test。
- FeatureGate 和 customer profile。
- 客户版内部调试解锁入口。

## 当前架构标注

- PySide6/Qt 是早期桌面阶段的历史事实；当前正式产品为 Electron Main + Preload + Vue，FastAPI/Python Core 是永久业务层。
- 旧编号 docs 中部分数据库和模块说明可能早于当前实现，后续以当前代码和专题文档为准。
