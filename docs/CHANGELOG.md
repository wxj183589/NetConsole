# NetConsole 更新日志

## v1.4.7 - 2026-08-05

### 局点与数据管理

- 局点列表新增线路名称和项目类型展示与维护，支持只修改显示名称的安全重命名；历史局点缺少字段时保持可读并明确提示未填写，不改动稳定 ID、物理目录和历史任务关联。
- 局点操作收敛为审计、查看清单、切换和“更多”菜单；普通非当前局点经完整名称强确认后原子移动到数据根 `.trash/`，当前局点、Demo、空壳局点、活动任务、锁定目录和越界路径均明确拒绝。原空壳 cleanup 与 Demo 重建流程保持独立。

### 工具集与设备任务交互

- 外部终端配置入口迁移到工具集，集中维护 SecureCRT、Xshell、PuTTY 的程序路径、默认终端、会话目录、端口和编码；旧系统设置链接继续兼容跳转，工具集可创建或复用终端快捷入口并实时校验路径。
- 设备任务生成 Artifact 和批量更新详情改用可持续通知展示，支持按具体任务另存、打开文件、定位目录和查看结果明细；通知在组件离开或完成操作后安全关闭，保存失败可直接重试。

### 轨旁 AP 主数据边界

- 轨旁 AP 业务工作区启用 singleton KeepAlive，保留查询、站点、仅异常筛选、分页、范围弹窗、任务和表格滚动位置；普通返回立即显示旧结果且不重复请求，数据过期或相关任务完成时静默刷新，局点切换淘汰旧请求和旧投影。
- 轨旁 AP 主表的车站交换机、AP MAC 和当前轨旁 AP 右键菜单统一显示“打开外部终端”，并保留复制单元格、复制整行；交换机使用业务行精确设备 UUID 及设备管理预检链，AP MAC 与当前轨旁 AP 使用同一组 FIT-AP `ac_id + ap_id` 并复用 AC 管理 options/launch、终端选择、提示和防重复逻辑，不按名称、MAC 或设备管理 AP 记录二次匹配，也不返回凭据。
- 2026-08-06 Electron 人工验收通过：轨旁 AP 业务切换页面后查询条件、分页和已有结果保持；右键车站交换机可打开对应交换机，右键 AP MAC 或当前轨旁 AP 可打开同一条 FIT-AP 资源目标，菜单文字、终端选择和成功/失败提示与 AC 管理一致。
- 基础资料编辑快照增加子页作用域：总览、站点与区间、轨旁 AP、轨旁 AP 规划、列车与车载 MR 各自锁定、加载基线、维护草稿、取消和保存；后端同时限制快照依赖与允许提交的实体类型，跨子页载荷在写事务前拒绝。
- 轨旁 AP 规划资格与主线区间拓扑资格拆分：启用的普通站、车辆段和停车场都生成逐站规划，车辆段/停车场保持节点类型且不生成主线区间；10 个普通站加 1 个车辆段稳定得到 11 行规划，新增特殊节点默认 AP 数为 0、VLAN 为空。
- 基础资料页改为每个子页独立的 `LOCKED / UNLOCKED_* / READ_ONLY` 交互；页面顶部不再承担全局解锁、保存或取消。脏子页切换提供“保存并切换 / 放弃并切换 / 取消切换”，目标子页保持自身锁定与草稿状态。
- 轨旁 AP 规划表移除数字输入步进控件及其占位，统一列宽来源，支持 Excel 多行粘贴、Enter 下移、Esc 恢复和滚轮防误改；规划页从设备管理生成时只接受正式 `matched_station_id`，不创建、解锁或保存站点。
- 新增物理 `devices.station_id`、`ap_extension_points.station_id/section_id` 及稳定 ID 迁移，统一事务按依赖顺序保存并在来源变化时只刷新一次 AP Identity；普通 GET 保持文件指纹只读。
- 修正轨旁 AP 页面与导出上线概览的统计边界：仅 AP 规划维护中带有效 `station_id` 的规划站点和已关联在线 AP 进入业务统计；未关联在线 AP 只作数据质量提示，不再生成伪站点行或进入上线合计。逐站和合计强制满足上线不超过规划、上线加未上线等于规划、上线率不超过 `100%`，AC/FIT-AP 全量资源数量保持不变。
- 轨旁 AP 业务改为以设备管理中的车站交换机候选端口和 AC FIT-AP/光衰运行态为主要生成来源；交换机尚未绑定基础资料 `station_id`、在线 AP 尚未匹配基础 AP 资料时仍生成业务行，基础资料只补充稳定站点和工程属性，页面诊断相应改为“基础资料待补充”。
- 修复轨旁 AP 上线概览在车站交换机尚未写入 `station_id` 时各站上线数全部为 0：运行态证据现在可将设备管理 `station` 与当前正式站点做唯一规范化匹配，再以交换机 LLDP 完整 AP MAC 精确关联 AC FIT-AP；歧义站名、多站同 MAC 和阶段不一致仍不计数，且不写回基础资料或设备绑定。
- 统一 AC/FIT-AP 与轨旁 AP 业务的 AP Rx 判定：最新有效值严格低于 `-13.90 dBm` 时标记“光衰大”，等于边界值仍为正常，空值、无效值或过期值不再默认为正常；后端陈旧 `normal` 不能覆盖明确低于门限的数值。`WA6522` 统一为“不适用”，不进入光衰异常数量、筛选或导出，也不使用交换机数值反推 AP 光衰。
- 修复 ZTE 车站交换机执行轨旁 AP 全部、站点或单 AP 更新时只刷新光模块、接口状态仍停留在旧快照：轻量分支现在同时采集 `show interface brief` 并更新管理/物理/协议/综合状态，沿用既有 PVID、VLAN 和端口模式等稳定详情，不增加逐端口详情命令。
- 收紧轨旁 AP 实时状态准入：每次交换机更新记录本轮采集标记，接口和光模块只有通过表头、非空和完整性校验后才成为当前快照；连接失败、空输出、解析失败或不完整结果会保留历史表但不再显示为当前链路和光功率，任务明确显示部分成功及失败数据域。页面分别展示接口和模块采集时间，历史时间带“历史数据”标记。
- 端口状态与模块状态拆分：接口 `DOWN` 时链路列显示 `DOWN`、综合列显示“链路断开”，交换机模块列继续显示模块正常、功率异常、无光或无模块，避免把端口状态误当作光模块故障。
- 补齐轨旁 AP 业务查询对交换机接口和光模块快照的时间、数据状态映射，采集时间不再显示为空，并分别区分当前与历史数据域。
- 轨旁 AP 业务显式返回交换机/AP/规划/最终站点身份和一致性原因；LLDP 生产关联只接受精确 MAC，IP、系统名和名称相似度降为诊断。
- 修复缺少基础 AP MAC 时轨旁 AP 业务无法显示规划归属站点：当前车站交换机 LLDP 的完整 AP MAC 与 FIT-AP 唯一精确匹配后，只读投影交换机稳定 `station_id`；多站点或无证据仍保持待关联，并在交换机绑定或 LLDP 更新后失效上线概览缓存。
- 站点名称统一保留基础资料中的显式编号并显示为 `01-站名`；设备来源生成兼容编号站点，轨旁 AP 业务按车站交换机、接口逻辑顺序升序展示，不再依赖设备管理中的站点名称排序。
- 旧规划兼容模板升级 schema v4 并要求车站 ID；迁移脚本默认 dry-run，apply 需副本哈希和显式确认，分域报告安全、歧义和未解析关系。

### MESH Peer 身份与来源治理

- AP Identity 新增物理 AP 单值/批量入口和 Peer 批量入口；批量查询在同一只读事务内固定 index/source revision 并集合读取 alias，每个结果携带本批 revision。
- MESH distinct Peer 映射改为一次 `resolve_peer_macs()`，identity-only remap 直接发布该批 revision，不在解析完成后重新读取版本。
- 地面无人值守移除基础资料、AC Radio 和 Alias 私有字典，历史页按 distinct Peer 批量解析，实时 Syslog 使用 revision-aware 缓存；物理 AP MAC 不再被当作 Peer Radio 证据，身份 entity/revision/status/source/reason 随既有事件详情持久化。
- 新增 AP Identity 消费者审计矩阵和架构门禁；AC Mesh-Link、Vehicle/Online MR、无线扫描及基础资料直查等遗留旁路列为显式后续项，不宣称已全部接管。
- MR/MESH Peer 生产匹配移除 H3C 36 位前缀和 Peer 名称回退，只接受实际 Radio/BSSID/BBSSID 或公共 R1/R2 函数生成的完整精确 alias；无证据和多候选分别保守返回 `unresolved/ambiguous`。
- H3C Radio alias 仅由明确 H3C、合法且末位为 `0` 的物理 AP MAC 生成；末位为 `F` 的 Radio 观测和非 H3C 数据不再二次衍生。合法 `source_revision=0` 不再误报索引过期，缺索引、过期、未采集精确 alias、未命中和重复 alias 分别返回可诊断原因。
- Identity source revision 只监听 AP 身份来源和被 FIT-AP 引用 AC 的厂商字段；无关设备与 `device_facts` 更新不再使索引过期。基础资料和光衰写任务在来源提交后按批次收口索引。
- 原始 Peer、Peer Radio 与解析物理 AP 身份在数据库查询、页面、图表、主链路、报告和链路明细中分层展示；同名不同 MAC 不再合并为同一物理 AP，历史 detail 库缺少新身份列时继续只读兼容。
- 健康的 MESH detail 库重新解析时只原子重映射 AP Identity 投影，保持原始 Peer、时间、RSSI、Busy、主备链、链路状态、样本和事件不变；detail 缺失、损坏或 schema 不兼容时才回退到受保护 raw 重建。
- 修复历史 MESH identity-only remap 的持久化键契约：mapping、resolve cache 和新写入链路键统一使用 12 位紧凑 MAC；单事务完成后回读校验覆盖、状态、行数和事实指纹，零写回不得发布 `ready`。健康 parsed 来源可通过维护脚本幂等恢复，无需改 schema 或重解析 raw。
- 修复 identity remap 完成后当前 MESH 详情仍显示旧身份投影：任务终态按受影响会话自动失效详情缓存，页面停用期间完成的任务在重新激活时刷新；顶部“刷新结果”同时读取概览、当前会话和活动标签，并保留筛选、分页与当前标签。
- 来源列表、批量操作和当前详情新增受控删除：可只删解析结果并从归档 raw 重建，也可删除当前数据根内归档副本、派生结果、指纹和关联报告后重新导入；外部原文件永不删除，失败使用 quarantine 补偿恢复。

### MESH 图表与导出

- 修复 MESH 主链与轨旁 RSSI 双图缩放不同步、轨旁数据被压成竖线和连续拖动回弹：图表重建后会恢复实际 DataZoom，拖动期间只本地同步 viewport，主链与轨旁窗口结果并行查询并成组发布；失败、413、取消和乱序响应保留上一组图表。
- 链路明细导出和主链路明细统一使用同一份 AP 位置快照，补全归属站点、区间、里程和方向；轨旁图文案统一为“轨旁 AP 信号图”，不再把不同业务图混称为普通轨旁信号。
- 修复 RSSI 零值连续段和降采样失真：同一自然秒内重复上报的 `0` 不再误判为持续区间，跨自然秒的持续区间保留精确边界，隐藏零值后的首个有效恢复点和关键帧不再丢失。
- RSSI 主链与轨旁 AP 图优先按自然秒保留真实采样；大日志安全渲染上限由 2,000 提升至 20,000 点，超过上限时按时间抽样并保留切换、异常、断点和极值等关键帧。

### Worker 协议与 FIT-AP 刷新

- 修复轨旁 AP 业务 XLSX 导出请求把 proposal 展示字段误发给严格 DTO 导致 422；前端现在只发送 `generated_at/suggested_name`，继续复用用户预选保存位置与 Export Process。
- 设备管理连接测试完成后主动重新加载设备列表，测试结果、连接状态和更新时间无需手工刷新即可显示。
- AC 总览、轨旁 AP 业务、AP 扩展、FIT-AP 资源读取和光衰读取的 Worker 终态改为计数、摘要和有界 Identity 聚合；配置正文/Diff 与旧无线扫描结果按 JSON 编码字节预算返回有界预览，完整配置和差异继续通过受管 Artifact 获取。
- 轨旁 AP 关联诊断明确区分 AC 侧 LLDP `conflict/multiple` 与唯一车站交换机 AP MAC 证据；冲突时保持待关联并提示重新采集 LLDP 或补充基础资料 MAC，不使用名称、IP 或运行状态强行归站。
- 修复 758 台 FIT-AP 光衰全部采集并入库后，完整资源、光衰和 Identity 明细形成约 4.81 MB（4,813,638 bytes）Worker 终态帧而导致任务失败；collect 终态改为有界持久化摘要，单 AP 日志耗时改为不含线程池排队时间，Windows 64 并发上限和设备命令保持不变。
- 修复大局点“更新 AC 信息”和单 AP“深度更新”在数据已成功入库后仍因完整资源快照超过 Worker 1 MiB 单帧限制而失败；两类任务改为返回有界持久化摘要，页面按 `reload_required` 重新读取 SQLite。
- FIT-AP collect 终态改为有界持久化摘要，不再携带完整资源列表；974 AP、758 LLDP 规模由任务摘要回执，页面通过分页 GET 重新加载 SQLite。
- FIT-AP 批量刷新加入 `display wlan ap all radio verbose filter bbssid`，使用独立 120 秒读取超时；该命令失败或空结果会保留 raw 并返回明确 BBSSID 状态，但不丢弃必需命令已采集的 AP 资源。
- FIT-AP 详细采集新增全量/选中两种受控范围，使用 `display wlan ap name <name> verbose` 写入 AP 与 Radio 详细表；目标由当前 AC 资源校验，任务终态只返回有界摘要，raw/命令记录仍保留。
- 修复 FIT-AP 直连 LLDP 两种动态表头的字段定位，支持 `System Name` 位于表首或表尾；邻居 MAC 优先匹配，泛化邻居名 `H3C/Comware/Switch` 不再单独绑定设备，多候选保留 `ambiguous`。
- 自动关联站点与手工元数据覆盖分离：基础资料 AP MAC、LLDP 交换机站点和 AC 原始站点仅作为只读证据，只有显式保存 `station_id` 才写入正式元数据。新增受控 LLDP 派生投影修复，默认 dry-run，显式 apply 才清理当前投影，历史与 raw 保持不变。
- 受控现场样本验证通过：H3C AC 资源刷新 974 台 FIT-AP、758 条 LLDP/Radio 证据；WA6522 与 WA6624X 直连 LLDP 两种表头各完成单台 raw 采集与解析。现场验证仍不等同于 Electron 全量人工验收。
- Worker 写帧前执行 1 MiB 字节检查，超大结果改发小型结构化错误；协议失败等待子进程退出后发布唯一终态，并在任务详情展示 reason、stream、frame/max bytes、exit code 和数据是否已落库，不影响 Backend 健康接口。

### 轨旁 AP 查询性能

- 轨旁 AP 逐站规划改为只读取 `ac_trackside_ap_plan(mode='unified')`；清空后维护页、上线概览、PVID 核验和共享范围均保持空规划，不再把历史 VLAN 分组或旧模式行投影成已删除规划。数据库初始化也停止从逐站规划生成历史 VLAN 分组，既有历史表和设备关联数据保持不变。
- 基础资料 AP 列表改为 SQLite 先筛选、排序、计数和分页，再只为当前页批量拼接 AC/MESH 运行态与质量问题；空占位行不再计入分页总数，普通 GET 不重建 Identity 或写业务 revision。
- AP 上线概览改为轻量聚合和 revision-aware 缓存，完整排除项与待关联在线 AP 改为按需分页接口；查询阶段耗时超过 2 秒记录 warning。
- 前端查询超时不再自动重试，同路径并发 GET 复用在途请求；自动重试仅保留 502/503/504 和明确的短暂网络错误，避免慢查询重复压入 Backend。

## v1.4.6 - 2026-07-30

### 全局查询部分刷新稳定性

- Online MR、无线综合看板、AC/FIT-AP、Agent 任务详情和局点存储查询改为按数据域独立结算；单个子接口失败时保留最后成功数据，成功接口仍立即更新。
- 失败提示统一为“部分数据刷新失败，已保留最后成功数据”，恢复时只清除对应域错误；基础资料和无线看板未加载指标显示 `—`，不再把未知状态当成真实 `0`。
- 新增覆盖单域失败、部分成功、单域恢复和保留旧数据的前端行为测试。实现提交：`a13eb8ac`。

### 基础资料部分刷新

- 基础资料总览、站点、区间、数据质量、轨旁 AP、列车、车载 MR、关联关系和导入治理改为按接口独立落值、独立恢复；单个接口失败时保留最后成功数据，并显示可展开的结构化错误，不再把 `/api/health` 在线误报为 Backend 整体离线。
- 轨旁 AP 规划与上线状态独立加载和提示；上线状态失败不影响规划表显示、编辑或真实校验计数。轨旁 AP 业务按来源区分未加载、部分可用、加载失败和真实零值，FIT-AP 或单台设备事实失败时保留已成功构建的候选端口行。
