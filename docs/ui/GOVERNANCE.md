# 存量例外与新增代码约束

当前项目已完成 UI 线程治理、导出进程化、表格性能、弹窗适配和编码兜底的主要收敛。后续开发按本文规则执行。

## 1. 存量合理例外

以下场景允许作为存量合理例外保留，但不得扩大使用范围：

1. 已有大表采用“硬上限 + 分批填充 + 完整数据后台导出”的方案，例如 SNMP、Network Toolbox、在线 MR 结果表。
2. 小型静态模板、小型说明文本、小型运行期结果可以使用 inline rows/text，但必须显式标注 `allow_inline_rows=True` 和 `inline_reason`。
3. 内部 background/export worker 的 JSONL/stdout/stderr 协议通道可以保留 UTF-8 replace 容错，但该例外不得用于设备回显、H3C 原始日志、MR 日志、SFTP/SSH 回显等外部文本。
4. 人工编辑型小表在有明确行数上限时可以保留少量 `setCellWidget`，但大表、结果表、文件列表、设备列表不得新增大量 cell widget。
5. `resize()` / `setMinimumSize()` 可作为默认窗口尺寸保留，但弹窗或子页内容超出时必须有滚动兜底或响应式布局。
6. 已有页面如果存在合理例外，只有在实际出现卡顿、遮挡、导出阻塞、编码损坏时才强制重构。

## 2. 新增代码强制规则

后续新增页面、弹窗、导出、后台任务、表格和文本读取必须遵守新规范：

1. UI 线程不得执行大查询、大文件读写、Excel/CSV 处理、长文本 diff、外部命令、日志解析、批量数据构建。
2. 导出按钮只创建导出任务，传递 source/filter/id/path/result_file，不得预先组装大 rows/text/items。
3. 大表必须采用分页、懒加载、Model/View、分批填充或明确硬上限；不得无上限 `setRowCount(len(all_rows))` 后逐格填充。
4. 新增大表不得使用大量 `setCellWidget`；复选框优先使用 item check state，操作优先使用右键菜单、工具栏动作或 delegate。
5. 顶部工具栏、筛选栏、按钮组不得硬塞进单行不可滚动布局；窄窗口下必须可横向滚动、换行或分组显示。
6. 新增参数 SpinBox 默认使用无上下箭头、禁用滚轮误触，除非业务明确需要微调按钮。
7. 弹窗、详情页、历史页、子页必须有滚动兜底；不能只靠固定最小尺寸防遮挡。
8. 外部文本、设备回显、日志、MIB、MR 原始文本读取必须按 `utf-8-sig -> utf-8 -> gb18030 -> gbk -> replace` 顺序兜底。
9. Worker、后台任务、导出进程必须在自身线程/进程内创建 repository/service/store，不得复用 UI 线程创建的实例。
10. 是否提交 Git 以当前用户要求为准；没有明确要求时不要自动提交。

## 3. 触碰即收敛原则

修改已有模块时，如果触碰到存量例外区域，应按以下原则处理：

1. 小改动不强制全模块重构，但不得新增同类风险。
2. 如果正在修改的函数已经涉及 UI 同步重活、导出 inline 大数据、大表无上限、弹窗遮挡风险，应一并收敛。
3. 如果保留例外，必须在代码注释或最终报告中说明原因、数据上限和风险边界。
4. 后续新增测试应覆盖新规范，不再为旧实现方式新增依赖。
