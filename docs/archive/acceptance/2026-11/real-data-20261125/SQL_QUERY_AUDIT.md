`GET /history` 默认保留精确总数。游标客户端可请求 `include_total=false`。该模式读取额外一条来判断是否存在下一页，并返回 `total_exact=false`。原有排序、过滤、游标约束和导出路径沿用既有实现。本阶段无 schema 或索引变更。

Ground 单一 Run 时间轴的探查 SQL 读取 `id, ts`，按 `ts DESC, id DESC` 排序。两套索引均命中覆盖索引 `idx_ground_events_timeline`，计划仍显示排序右侧使用临时 B-tree。这个探查的两线 25 行查询分别在 0.014–0.160 ms 和 0.015–0.111 ms，混合历史使用多个来源以及以 `julianday` 归一的时间排序，耗时应按上表评估。

HZL10 的读取规模复核为 Ground 事件 616,103、MESH 事件 297,397、AC 快照 358,870、Ping Summary 562,861 和 MR 链路 1,999,008。Quick Ping 专用 Run 为零，HZL9 对应为两个。

HZL10 混合历史当前仍高于 500 ms 目标。五次采样仅作为阶段基线，P95/P99、大窗口聚合、混合负载和持续运行待实测。真实 Electron 端到端结果待验收。
