# Electron-only E5 启动性能归档

## 结论

2026-07-18 已为 Electron Desktop 建立单调时钟启动时间线，并把历史任务恢复、Agent/Traffic/File 运行服务恢复移出首屏关键路径。Netmiko 只在首次真实设备连接时加载，OpenPyXL 只在首次工作簿读写时加载；这些调整没有改变设备命令、业务 DTO、数据库 schema 或启动超时。

连续两个独立 Electron 冒烟进程的 `desktop.interactive` 为 1991.2 ms 和 2068.2 ms，中位数 2029.7 ms。相对同一时间线下的整改前基线 2926.8 ms，中位改善 30.6%。加载状态页分别在 101.4 ms 和 112.3 ms 可见。

## 时间线

Electron 日志使用 `process.hrtime.bigint()` 记录：

```text
electron.app_ready
electron.window_created
electron.loading_view_shown
backend.spawn_started
backend.handshake_received
backend.health_ready
renderer.navigation_started
renderer.dom_ready
renderer.mounted
desktop.interactive
```

Renderer 先挂载基础页面，再异步加载设置并验证真实 `/api/health`。`mounted` 只表示 Vue 已挂载，只有健康检查成功后的 `interactive` 才满足桌面可交互门；冒烟退出仍等待页面稳定，不以白屏或单纯 HTTP 监听冒充成功。

Python `create_app(RuntimeMode.DESKTOP)` 的定向计时从约 604.6 ms 降至约 281 ms。独立 Backend 主模块导入仍约 1.3 秒，是后续可继续分析的最大固定成本；本阶段不为追求数字拆散 Router 或建立第二套轻量 Backend。

## 实施边界

- Desktop 会话下的 Task/Traffic 构造不再同步 reconcile；生命周期启动后延迟 1 秒恢复 Task、Agent、Traffic 和文件下载队列。
- 普通 `server` 模式仍保持同步启动及失败回滚语义。
- `netmiko_connection.ConnectHandler` 的公共兼容入口保留，首次真实调用才导入 Netmiko/Paramiko。
- 车内通信与 AC Mesh 查询中的车辆身份解析保持同一事实源，只把导入时机延后。
- `excel_workbook.load_workbook` 兼容入口保留，OpenPyXL 在实际 XLSX 读写时加载。
- 没有增加无认证调试接口、任意命令入口、额外 Renderer 或永久 Token。
