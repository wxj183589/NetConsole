## 2. 不再变更的产品决策

1. 正式桌面产品只有 Electron Main + Preload + Vue Renderer；FastAPI/Python Core 是永久业务层。
2. Qt/PySide6/QFluentWidgets 的活动源码、入口、依赖和发布链已退出，不得重新引入。无参数 `main.py` 是 PyCharm/源码态 Electron 启动入口。
3. Browser 只用于回环地址上的开发、联调和诊断，不是第二个正式产品，也不设置自动 Browser 回退。
4. SNMP Center、通用 MIB/OID 平台和无线勘测已删除；历史用户数据库和文件不做破坏性清理。设备管理只保留 SNMP v1/v2c 只读基础识别，不支持 SNMPv3、SET、任意 OID 或 MIB 上下文。
5. CentOS 7 与 Windows Legacy 兼容包暂不纳入当前发布和验收门，不得阻塞 `main`；Windows 当前桌面和 Windows Go Agent 是活动目标。
6. fping/iPerf3 正式构建只允许复制仓库 `resources/tools/` 中已版本化、已校验的本地文件，不在构建时联网下载业务工具，不从根 `tools/`、`apps/agent/tools/` 或开发机任意路径取件。
7. 业务能力继续遵守 `Application Service -> FastAPI -> Vue`；Electron 只承载窗口、受管进程和白名单 Native Bridge，不增加任意 Shell、SQL、路径或程序执行后门。

## 5. E2 已固定边界

E2 已固定四个边界，后续不得绕过：

1. **依赖闭包**：`requirements-runtime.txt`、`requirements-test.txt`、`requirements-build.txt`、`requirements-dev.txt` 与 `constraints.txt` 分层；运行依赖、打包工具和开发工具不得混入彼此的产品声明。
2. **最终制品事实**：不能只检查 requirements；必须从 PyInstaller Analysis/最终归档核对实际进入 Backend 的 distribution，并与最终 SBOM、Notice 和许可证材料精确一致，拒绝重复、缺失和环境漂移组件。
3. **本地工具供应链**：fping 固定为上游 v5.5 加仓库归档补丁/配方；iPerf3 固定为 3.21 `win64-dynamic-auth` 运行文件。主程序与 Agent 构建都要在复制前后校验精确文件集合、哈希、来源和许可证。
4. **发布隔离**：生产包不得包含 Qt、Vite、开发接口、默认 DevTools、开发 Token、源码数据目录或未知工具文件；安装包 smoke 还要检查受管 Backend 生命周期、回环监听与退出清理。

许可证合规不是一次性测试结论。每次分发包含 Cygwin DLL 的正式制品时，发布负责人仍须按对应 `CORRESPONDING_SOURCE.md` 提供相同版本的对应源码材料或有效书面提供方案。
