# Electron-only E4 数据目录迁移归档

## 结论

2026-07-18 已将源码开发态活动数据根从仓库 `.local/` 切换到 `%LOCALAPPDATA%\NetConsole\Development\`。打包态继续使用 `%LOCALAPPDATA%\NetConsole\`。`PathResolver.app_root` 与 `data_root` 已解耦，Electron Main 会明确向受管 Backend 传递数据根和运行模式，并拒绝位于项目/安装目录内的目标。

本阶段没有删除仓库业务数据。仓库 `.local/data`、`.local/runtime` 和根 `data` 仍作为只读迁移源保留，供后续确认和回退；`main.py`/Electron 启动不再读写它们。

## 迁移执行记录

- 迁移目标：Windows 当前用户的 `NetConsole/Development` 应用数据目录。
- 计划条目：10859。
- 实际无覆盖复制：9874 个文件，约 4.06 GB（十进制）。
- SQLite：398 个数据库通过 SQLite Backup API 复制并执行源/目标 `PRAGMA quick_check`。
- 跳过：982 个 SQLite `-wal/-shm/-journal` 瞬态 sidecar；正式数据库快照已包含可见事务。
- 冲突：根 `data` 中 `config/app.json`、demo `devices.db`、demo `tasks.db` 与较新的 `.local` 源不同，按 `.local` 优先规则保留且不覆盖。
- 清理：仅删除 `.local` 顶层 54 个明确 `pytest-*`/Qt 临时项，共 761854437 字节；`data`、`runtime`、`acceptance`、`tmp`、`agent_team` 全部保持。
- 完整本机 manifest 保存在当前用户应用数据目录的 `NetConsole/MigrationReports`，不提交真实局点相对路径到仓库。

## 安全工具

- `scripts/maintenance/migrate_legacy_runtime_data.py`：默认 dry-run；限定三个历史源，拒绝链接/路径逃逸，不覆盖目标，复制后校验哈希，SQLite 使用 Backup API。
- `scripts/maintenance/clean_test_artifacts.py`：默认 dry-run；只识别 `.local` 顶层明确测试/Qt 临时前缀，业务、验收和未知目录默认保护。

两个工具都必须先审查 manifest；迁移冲突只能显式 `--skip-conflicts` 保留，不能自动覆盖。

## 验证

- 数据路径/Runtime/Launcher 定向 Python：53 passed。
- Electron：75 passed，TypeScript typecheck 通过。
- 新增迁移/清理工具：4 passed；相关 Ruff 通过。
- 基于迁移后真实数据执行 `main.py` Electron smoke：退出码 0，5173 无监听残留。
- smoke 前后仓库 `.local` 与根 `data` 的文件数、总字节和最新修改时间一致，证明活动运行链没有写回源码树。

## 保留项

- 仓库历史业务数据尚未删除；只有在用户完成 Electron 人工验收、确认目标数据完整且回退期结束后，才可单独执行删除评审。
- 根 `data` 的三个冲突项继续保留在源目录，不进入目标；如需比较内容，必须使用只读 SQLite/JSON 审计，不得覆盖较新的 `.local` 版本。
- 本阶段不处理数据库 schema/索引优化；任何 E6 数据库修改都必须以独立性能证据和迁移/回滚方案为前提。
